# Развёртывание обработчика заявок (Yandex Cloud)

Форма на сайте отправляет заявки в функцию Yandex Cloud (`index.py`), а та пересылает их письмом на рабочие адреса.
Файлы из формы браузер загружает в закрытый бакет Object Storage, функция прикладывает их к письму и удаляет из бакета.

```
Браузер ──(1) init: список файлов──────────▶ Функция ── временные ссылки на загрузку ──▶ Браузер
Браузер ──(2) PUT файлов по ссылкам────────▶ Object Storage (бакет, закрытый)
Браузер ──(3) submit: имя, контакт, ключи──▶ Функция ── скачивает файлы ── SMTP ──▶ почта
                                                     └─ удаляет файлы из бакета
```

Почему не напрямую: запрос к функции ограничен 3,5 МБ, а base64 увеличивает файлы на треть,
поэтому файлы до 10 МБ передать через функцию нельзя.

Всё делается в веб-консоли https://console.yandex.cloud. Для небольшого потока заявок
расходы укладываются в бесплатный лимит (Cloud Functions и первый 1 ГБ Object Storage).

---

## 1. Почтовый ящик для отправки

Письма отправляются от имени отдельного ящика (например, `site-leads@mail.ru` или ящик на Яндекс Почте).

1. Создайте ящик (или используйте существующий служебный).
2. Создайте **пароль приложения** — обычный пароль от почты не подойдёт:
   - Mail.ru: «Настройки → Безопасность → Пароли для внешних приложений»;
   - Яндекс Почта: «Управление аккаунтом → Безопасность → Пароли приложений», тип «Почта».
     Также в настройках почты включите «Почтовые программы → доступ по протоколу IMAP».
3. Параметры SMTP:

| Почта | SMTP_HOST | SMTP_PORT |
|---|---|---|
| Mail.ru | `smtp.mail.ru` | `465` |
| Яндекс | `smtp.yandex.ru` | `465` |

`SMTP_USER` — полный адрес этого ящика. Почтовые серверы отклоняют письма, у которых
отправитель не совпадает с ящиком, поэтому подставлять другой адрес нельзя.

## 2. Бакет Object Storage

1. **Object Storage → Создать бакет.**
   - Имя: например, `reversprom-leads` (уникальное во всём Yandex Cloud).
   - Доступ на чтение объектов, к списку объектов и настройкам: **ограниченный** (все три).
   - Класс хранилища: стандартное. Максимальный размер: например, 1 ГБ.
2. **Бакет → Безопасность → CORS → Настроить** — добавьте правило:
   - Allowed Origins: адрес сайта на GitHub Pages — `https://alksndrkzntsv.github.io`;
     для локальной проверки — `http://localhost:8080`. Указывается только схема и домен, без `/Reversprom`;
   - Allowed Methods: `PUT`;
   - Allowed Headers: `Content-Type`;
   - MaxAgeSeconds: `3600`.

   Без этого правила браузер не сможет загрузить файлы, и на сайте появится ошибка
   «не удалось загрузить файл … (нет соединения с хранилищем)».
3. **Бакет → Жизненный цикл → Настроить** — правило-страховка на случай, если посетитель
   загрузил файлы, но не отправил заявку:
   - префикс `leads/`, действие «Удаление объектов» (Expiration), через **1 день**.

## 3. Сервисный аккаунт и ключ доступа к бакету

1. **Identity and Access Management → Сервисные аккаунты → Создать**: имя `reversprom-leads`.
2. Выдайте ему роль `storage.editor`. Лучше выдавать её только на этот бакет
   (бакет → «Права доступа»), а если такой возможности нет — на каталог.
3. Откройте сервисный аккаунт → **Создать новый ключ → Статический ключ доступа**.
   Сохраните **идентификатор ключа** (`S3_ACCESS_KEY`) и **секретный ключ** (`S3_SECRET_KEY`):
   секретный ключ показывается только один раз.

## 4. Функция

1. **Cloud Functions → Создать функцию**: имя `reversprom-lead`.
2. На вкладке «Обзор» включите **«Публичная функция»**: сайт вызывает её без авторизации.
3. **Редактор:**
   - среда выполнения: **Python 3.12** (`python312`);
   - способ: редактор кода, создайте файл `index.py` и вставьте содержимое `index.py` из репозитория;
   - точка входа: `index.handler`;
   - таймаут: **60 с**; память: **256 МБ** (письмо с файлами на 10 МБ собирается в памяти);
   - переменные окружения:

| Переменная | Пример | Назначение |
|---|---|---|
| `SMTP_HOST` | `smtp.mail.ru` | SMTP-сервер почты из шага 1 |
| `SMTP_PORT` | `465` | 465 — SSL; другой порт — STARTTLS |
| `SMTP_USER` | `site-leads@mail.ru` | ящик-отправитель |
| `SMTP_PASSWORD` | пароль приложения | см. шаг 1 |
| `TO_EMAILS` | `info@reversprom.ru,sales@gmail.com` | куда приходят заявки, через запятую |
| `S3_BUCKET` | `reversprom-leads` | имя бакета из шага 2 |
| `S3_ACCESS_KEY` | идентификатор ключа | из шага 3 |
| `S3_SECRET_KEY` | секретный ключ | из шага 3 |
| `ALLOWED_ORIGIN` | `http://localhost:8080,https://alksndrkzntsv.github.io` | адреса сайта без пути и `/` в конце, через запятую; должны совпадать с Allowed Origins в CORS бакета |

   Пароль и секретный ключ надёжнее хранить в **Lockbox** и подключить к функции как секреты
   (тогда функции нужен сервисный аккаунт с ролью `lockbox.payloadViewer`). Обычные переменные
   окружения тоже работают, но видны всем, у кого есть доступ к функции в консоли.
4. Нажмите **«Сохранить изменения»** и скопируйте **ссылку для вызова** вида
   `https://functions.yandexcloud.net/d4e...`.

## 5. Подключение сайта

1. В `index.html` замените значение `LEAD_ENDPOINT` на ссылку из шага 4:
   ```js
   const LEAD_ENDPOINT = 'https://functions.yandexcloud.net/d4e...';
   ```
2. Закоммитьте и отправьте в `main` — GitHub Pages обновит сайт автоматически.

## 6. Проверка

1. Откройте сайт на GitHub Pages (https://alksndrkzntsv.github.io/Reversprom/) и отправьте заявку:
   - без файлов;
   - с несколькими файлами (фото, PDF, STEP), в том числе с русскими именами, всего 5–10 МБ.
2. Письма должны прийти на все адреса из `TO_EMAILS`, с вложениями.
   Проверьте папку «Спам» — первые письма от нового ящика иногда попадают туда.
3. Бакет после успешной отправки должен остаться пустым.
4. Если что-то не так — **функция → Логи**. Посетителю сайта показываются только общие сообщения,
   подробности ошибок (SMTP, Object Storage, незаданные переменные) пишутся в лог.

| Симптом на сайте | Вероятная причина |
|---|---|
| «Сервер заявок не настроен» | не заданы переменные окружения (список — в логе функции) |
| «Не удалось отправить письмо» | неверный `SMTP_USER`/`SMTP_PASSWORD`, обычный пароль вместо пароля приложения |
| «не удалось загрузить файл … (нет соединения с хранилищем)» | нет правила CORS у бакета или в нём другой адрес сайта |
| «не удалось загрузить файл … (HTTP 403)» | неверный ключ доступа или у сервисного аккаунта нет роли `storage.editor` |
| «Failed to fetch» до загрузки файлов | функция не публичная или неверный `LEAD_ENDPOINT` |

## Согласованность настроек

Эти значения продублированы в `index.html` и `index.py` и должны совпадать:

| index.html | index.py |
|---|---|
| `MAX_BYTES` (10 МБ) | `MAX_TOTAL_BYTES` |
| `MAX_FILES` (10) | `MAX_FILES` |
| `ALLOWED_EXTENSIONS` и атрибут `accept` у поля файла | `ALLOWED_EXTENSIONS` |

Лимит на вложения ограничен почтой: письмо получается примерно на треть больше файлов, а
Gmail и Mail.ru принимают письма до ~25 МБ. Поднимать лимит выше ~15 МБ не стоит.
