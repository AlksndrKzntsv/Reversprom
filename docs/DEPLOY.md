# Развёртывание (Yandex Cloud)

Всё размещено в Yandex Cloud, настройка — в веб-консоли https://console.yandex.cloud.

| Что | Где |
|---|---|
| Сайт `https://reverseprom.ru` | бакет Object Storage `reverseprom.ru` (режим «Веб-сайт») |
| `https://www.reverseprom.ru` | бакет `www.reverseprom.ru`, переадресация на адрес без www |
| HTTPS | сертификат Let's Encrypt в Certificate Manager |
| DNS домена | зона `reverseprom.ru.` в Cloud DNS (домен зарегистрирован на reg.ru) |
| Обработчик формы | функция `reversprom-lead` (Cloud Functions) + закрытый бакет `reversprom-leads` |
| Почта `info@reverseprom.ru` | Яндекс 360 для бизнеса |

---

# Часть 1. Сайт

## 1.1. Бакеты

1. **Object Storage → Создать бакет** `reverseprom.ru` (имя должно совпадать с доменом):
   - чтение объектов — **для всех**; чтение списка объектов и настроек — **с авторизацией**.
2. **Бакет → Настройки → Веб-сайт → «Хостинг»**: главная страница и страница ошибки — `index.html`.
3. Бакет `www.reverseprom.ru` с теми же правами доступа, **Веб-сайт → «Переадресация»**:
   домен `reverseprom.ru`, протокол `https`. Файлы в него не загружаются.

## 1.2. Cloud DNS

Зона `reverseprom.ru.`, публичная. DNS-серверы домена на reg.ru: `ns1.yandexcloud.net`, `ns2.yandexcloud.net`.

| Имя | Тип | Значение | Назначение |
|---|---|---|---|
| `@` | ANAME | `reverseprom.ru.website.yandexcloud.net` | сайт |
| `www` | CNAME | `www.reverseprom.ru.website.yandexcloud.net` | сайт |
| `@` | MX | `10 mx.yandex.net.` | почта |
| `@` | TXT | `v=spf1 redirect=_spf.yandex.net` | почта, SPF |
| `mail._domainkey` | TXT | DKIM-ключ из admin.yandex.ru → Домены → DKIM-подпись | почта, DKIM |
| `_dmarc` | TXT | `v=DMARC1; p=none; rua=mailto:info@reverseprom.ru` | почта, DMARC |
| `@` | TXT | `yandex-verification: …` | подтверждение домена в Яндекс 360 |
| `_acme-challenge…` | CNAME | выдаёт Certificate Manager | продление сертификата |

**Почтовые записи не удаляйте** — без них `info@reverseprom.ru` перестанет принимать и отправлять письма.

## 1.3. Сертификат HTTPS

1. **Certificate Manager → Добавить сертификат → Let's Encrypt**: домены `reverseprom.ru`, `www.reverseprom.ru`,
   проверка через DNS; записи `_acme-challenge` — в зону Cloud DNS.
2. В **обоих** бакетах: **Настройки → HTTPS → Certificate Manager** → этот сертификат.

Сертификат продлевается автоматически, пока записи `_acme-challenge` есть в зоне.

## 1.4. Публикация сайта (`deploy.sh`)

Скрипт загружает в бакет содержимое папки `site/` и удаляет из бакета всё, чего в `site/` нет.

**Однократная настройка:**

1. **Identity and Access Management → Сервисные аккаунты → Создать** `site-deploy`.
   Выдайте роль `storage.editor` на бакет `reverseprom.ru` (бакет → «Права доступа»).
2. Сервисный аккаунт → **Создать новый ключ → Статический ключ доступа**; сохраните идентификатор и секретный ключ.
3. Установите AWS CLI и создайте профиль:
   ```bash
   brew install awscli
   aws configure --profile reverseprom
   # AWS Access Key ID:     идентификатор ключа
   # AWS Secret Access Key: секретный ключ
   # Default region name:   ru-central1
   # Default output format: (Enter)
   ```
   Ключи сохраняются в `~/.aws/credentials`, вне репозитория.

**Каждая публикация:**

```bash
git commit ...           # сначала закоммитьте изменения
./deploy.sh --dryrun     # посмотреть, что изменится
./deploy.sh              # опубликовать
```

Обновите страницу с очисткой кеша (Cmd+Shift+R) и проверьте изменения на https://reverseprom.ru.

# Часть 2. Обработчик заявок

Форма на сайте отправляет заявки в функцию Yandex Cloud (`function/index.py`), а та пересылает их письмом на рабочие адреса.
Файлы из формы браузер загружает в закрытый бакет Object Storage, функция прикладывает их к письму и удаляет из бакета.

```
Браузер ──(1) init: список файлов──────────▶ Функция ── временные ссылки на загрузку ──▶ Браузер
Браузер ──(2) PUT файлов по ссылкам────────▶ Object Storage (бакет, закрытый)
Браузер ──(3) submit: имя, контакт, ключи──▶ Функция ── скачивает файлы ── SMTP ──▶ почта
                                                     └─ удаляет файлы из бакета
```

Почему не напрямую: запрос к функции ограничен 3,5 МБ, а base64 увеличивает файлы на треть,
поэтому файлы до 10 МБ передать через функцию нельзя.

Для небольшого потока заявок расходы укладываются в бесплатный лимит (Cloud Functions и первый 1 ГБ Object Storage).

## 2.1. Почтовый ящик для отправки

Письма отправляются от имени ящика `reverseprom@mail.ru` (отдельный платный ящик в Яндекс 360 для этого не нужен).

1. Создайте **пароль приложения** — обычный пароль от почты не подойдёт:
   - Mail.ru: id.mail.ru → «Безопасность» → «Пароли для внешних приложений»;
   - Яндекс Почта: «Управление аккаунтом → Безопасность → Пароли приложений», тип «Почта».
     Также в настройках почты включите «Почтовые программы → доступ по протоколу IMAP».
2. Параметры SMTP:

| Почта | SMTP_HOST | SMTP_PORT |
|---|---|---|
| Mail.ru | `smtp.mail.ru` | `465` |
| Яндекс | `smtp.yandex.ru` | `465` |

`SMTP_USER` — полный адрес этого ящика. Почтовые серверы отклоняют письма, у которых
отправитель не совпадает с ящиком, поэтому подставлять другой адрес нельзя.

## 2.2. Бакет для файлов заявок

1. **Object Storage → Создать бакет** `reversprom-leads`.
   - Доступ на чтение объектов, к списку объектов и настройкам: **ограниченный** (все три).
   - Класс хранилища: стандартное. Максимальный размер: например, 1 ГБ.
2. **Бакет → Безопасность → CORS** — правила (по одному на каждый адрес):
   - Allowed Origins: `https://reverseprom.ru`, `https://www.reverseprom.ru`, `http://localhost:8080`.
     Только схема и домен, без пути и `/` в конце;
   - Allowed Methods: `PUT`;
   - Allowed Headers: `Content-Type`;
   - MaxAgeSeconds: `3600`.

   Без этих правил браузер не сможет загрузить файлы, и на сайте появится ошибка
   «не удалось загрузить файл … (нет соединения с хранилищем)».
3. **Бакет → Жизненный цикл** — правило-страховка на случай, если посетитель
   загрузил файлы, но не отправил заявку: префикс `leads/`, «Удаление объектов» через **1 день**.

## 2.3. Сервисный аккаунт и ключ доступа к бакету

1. **Identity and Access Management → Сервисные аккаунты → Создать**: имя `reversprom-leads`.
2. Выдайте ему роль `storage.editor` на бакет `reversprom-leads`.
3. Сервисный аккаунт → **Создать новый ключ → Статический ключ доступа**.
   Сохраните **идентификатор ключа** (`S3_ACCESS_KEY`) и **секретный ключ** (`S3_SECRET_KEY`):
   секретный ключ показывается только один раз.

## 2.4. Функция

1. **Cloud Functions → Создать функцию**: имя `reversprom-lead`.
2. На вкладке «Обзор» включите **«Публичная функция»**: сайт вызывает её без авторизации.
3. **Редактор:**
   - среда выполнения: **Python 3.12** (`python312`);
   - способ: редактор кода, создайте файл `index.py` и вставьте содержимое `function/index.py` из репозитория;
   - точка входа: `index.handler`;
   - таймаут: **60 с**; память: **256 МБ** (письмо с файлами на 10 МБ собирается в памяти);
   - переменные окружения:

| Переменная | Значение | Назначение |
|---|---|---|
| `SMTP_HOST` | `smtp.mail.ru` | SMTP-сервер почты из шага 2.1 |
| `SMTP_PORT` | `465` | 465 — SSL; другой порт — STARTTLS |
| `SMTP_USER` | `reverseprom@mail.ru` | ящик-отправитель |
| `SMTP_PASSWORD` | пароль приложения | см. шаг 2.1 |
| `TO_EMAILS` | `info@reverseprom.ru,…` | куда приходят заявки, через запятую |
| `S3_BUCKET` | `reversprom-leads` | бакет из шага 2.2 |
| `S3_ACCESS_KEY` | идентификатор ключа | из шага 2.3 |
| `S3_SECRET_KEY` | секретный ключ | из шага 2.3 |
| `ALLOWED_ORIGIN` | `http://localhost:8080,https://reverseprom.ru,https://www.reverseprom.ru` | адреса сайта без пути и `/` в конце, через запятую; должны совпадать с CORS бакета |

   Пароль и секретный ключ надёжнее хранить в **Lockbox** и подключить к функции как секреты
   (тогда функции нужен сервисный аккаунт с ролью `lockbox.payloadViewer`). Обычные переменные
   окружения тоже работают, но видны всем, у кого есть доступ к функции в консоли.
4. Нажмите **«Сохранить изменения»** и скопируйте **ссылку для вызова** вида
   `https://functions.yandexcloud.net/d4e...`.
5. Если ссылка изменилась — пропишите её в `LEAD_ENDPOINT` в `site/index.html` и опубликуйте сайт (`./deploy.sh`).

Правки `function/index.py` в репозитории на работу формы не влияют, пока в редактор функции не вставлен новый код и не сохранена новая версия (пункты 3–4).

## 2.5. Проверка

1. Откройте https://reverseprom.ru и отправьте заявку:
   - без файлов;
   - с несколькими файлами (фото, PDF, STEP), в том числе с русскими именами, всего 5–10 МБ.
2. Письма должны прийти на все адреса из `TO_EMAILS`, с вложениями.
   Проверьте папку «Спам» — первые письма от нового ящика иногда попадают туда.
3. Бакет `reversprom-leads` после успешной отправки должен остаться пустым.
4. Если что-то не так — **функция → Логи**. Посетителю сайта показываются только общие сообщения,
   подробности ошибок (SMTP, Object Storage, незаданные переменные) пишутся в лог.

| Симптом на сайте | Вероятная причина |
|---|---|
| «Сервер заявок не настроен» | не заданы переменные окружения (список — в логе функции) |
| «Не удалось отправить письмо» | неверный `SMTP_USER`/`SMTP_PASSWORD`, обычный пароль вместо пароля приложения |
| «не удалось загрузить файл … (нет соединения с хранилищем)» | нет правила CORS у бакета или в нём другой адрес сайта |
| «не удалось загрузить файл … (HTTP 403)» | неверный ключ доступа или у сервисного аккаунта нет роли `storage.editor` |
| «Failed to fetch» до загрузки файлов | функция не публичная, неверный `LEAD_ENDPOINT` или адреса нет в `ALLOWED_ORIGIN` |

## Согласованность настроек

Эти значения продублированы в `site/index.html` и `function/index.py` и должны совпадать:

| site/index.html | function/index.py |
|---|---|
| `MAX_BYTES` (10 МБ) | `MAX_TOTAL_BYTES` |
| `MAX_FILES` (10) | `MAX_FILES` |
| `ALLOWED_EXTENSIONS` и атрибут `accept` у поля файла | `ALLOWED_EXTENSIONS` |

Лимит на вложения ограничен почтой: письмо получается примерно на треть больше файлов, а
Gmail и Mail.ru принимают письма до ~25 МБ. Поднимать лимит выше ~15 МБ не стоит.
